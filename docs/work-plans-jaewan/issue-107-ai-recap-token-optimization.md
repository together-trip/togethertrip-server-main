# 이슈 107 AI Recap 이미지 토큰 최적화 작업 계획

## 작업 정보

- 이슈: [#107 AI Recap 이미지 생성 토큰 사용량 최적화](https://github.com/together-trip/togethertrip-server-main/issues/107)
- 브랜치: `feature/issue-107-ai-recap-token-optimization`
- 시작점: `develop`의 `0b40b96`
- 사용자 관측값: 이미지 생성 16요청에서 32,423토큰
- 목표: 이미지 수를 줄이지 않고 비용, 토큰, 지연시간을 줄인다.
- 구현 원칙: Spring AI `ImageModel`을 이미지 생성의 주 추상화로 사용한다.

## 반드시 지킬 실행 순서

최적화는 아래 여섯 단계를 순서대로 진행한다. 각 단계는 반드시 구현, 동일한 16요청 측정, 품질 확인, 문서화, 독립 커밋까지 완료한 뒤 다음 단계로 넘어간다. 구현 결과가 효과가 없거나 품질 기준을 통과하지 못해도 수치와 롤백 판단을 문서에 남긴다.

1. 토큰 사용량 계측과 기준선 확정
2. 프롬프트 축약
3. 참조 이미지 입력 최적화
4. 출력 크기와 품질 프로파일 최적화
5. 모델 라우팅 검증
6. 캐시, 중복 요청, 재시도, 다중 이미지 요청 최적화

## 고정 비교 세트

매 단계는 총 16회의 외부 이미지 요청을 사용한다.

- 3장 PHOTO 생성 경로: 3요청
- 5장 ILLUSTRATION 생성 경로: 5요청
- 7장 PHOTO 참조 편집 경로: 7요청
- ILLUSTRATION 참조 편집 보완: 1요청
- 합계: 생성 8요청, 편집 8요청
- 참조 편집은 동일한 256×256 PNG fixture 한 장을 사용한다.

`3 + 5 + 7`은 15이므로, 16요청을 유지하면서 두 스타일과 생성/편집을 모두 포함하기 위해 ILLUSTRATION 편집 1건을 추가한다. 현재 운영 구현은 한 장면마다 이미지 API를 한 번 호출하므로, 기준선에서는 사진 1장당 요청 1회다. 호출 횟수 개선은 6단계에서 별도로 검증한다.

## 공통 측정 지표와 품질 게이트

- 요청 수, 성공률
- 총 토큰, 요청당 토큰
- 입력 토큰: 텍스트, 이미지, 캐시 입력
- 출력 토큰
- 예상 비용
- p50, p95 응답시간
- 프롬프트 문자 수
- 출력 해상도와 9:16 비율
- PHOTO/ILLUSTRATION 스타일 구분
- 여행 맥락 유지
- 얼굴 클로즈업이나 식별 가능한 인물 없음
- 텍스트, 로고, 워터마크 없음

16장 중 하나라도 필수 안전·형식 기준을 위반하면 해당 설정을 기본값으로 채택하지 않는다.

## Spring AI 적용 범위

- Spring AI 2.0.0 BOM과 `spring-ai-openai`를 사용한다.
- 생성은 Spring AI `ImageModel.call(ImagePrompt)` 계약으로 실행한다.
- Spring AI의 이식 가능한 `ImageModel`은 이미지 편집 입력과 OpenAI 상세 usage를 제공하지 않는다. 편집은 Spring AI가 채택한 공식 OpenAI Java SDK와 `SpringAiOpenAiHttpClient`로 보완하고, 결과를 Spring AI `ImageResponse`로 변환한다.
- SDK의 숨은 중복 호출을 막기 위해 현재 단계에서는 자동 재시도를 0으로 둔다. 재시도 정책은 6단계에서 계측 후 결정한다.

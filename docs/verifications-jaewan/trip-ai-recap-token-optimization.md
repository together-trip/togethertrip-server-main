# AI Recap 이미지 토큰 최적화 검증 기록

## 비교 규칙

- 이슈 [#107](https://github.com/together-trip/togethertrip-server-main/issues/107)의 고정 16요청 세트를 모든 단계에서 반복한다.
- 단계별 코드, 모델, 크기, 품질, 참조 입력 조건을 함께 기록한다.
- 사용자 제공 32,423토큰은 기존 운영 관측값이며 fixture가 동일하다고 확인되지 않았으므로 참고값으로만 비교한다.
- 단계 간 개선율은 이 문서의 1단계 Spring AI 기준선 28,312토큰을 분모로 계산한다.
- 비용은 측정 시점의 `gpt-image-2` 단가인 텍스트 입력 $5/백만 토큰, 이미지 입력 $8/백만 토큰, 이미지 출력 $30/백만 토큰으로 추정한다.

## 1단계: Spring AI 계측과 기준선

### 구현

- Spring AI 2.0.0 `ImageModel` 기반 생성 경로를 도입했다.
- Spring AI 공식 OpenAI SDK/HTTP 전송 계층으로 편집 API를 보완했다.
- OpenAI 응답의 상세 usage를 Spring AI `ImageResponseMetadata`에 보존한다.
- 생성/편집, 모델, 크기, 품질, 참조 이미지 수, 성공 여부, 지연시간, 토큰과 실패 유형을 구조화 로그로 남긴다.
- 공식 SDK의 자동 재시도는 0으로 설정해 기준선에서 숨은 중복 호출을 배제했다.
- 실 API 테스트는 `OPENAI_LIVE_BENCHMARK_APPROVED=true`일 때만 실행된다.

- 장면 순서에 맞는 장소/국가/활동 신호를 하나씩 선택한다.
- 사용자 메타데이터의 연속 공백을 정규화하고 focus 120자, 국가 80자, 활동 40자로 제한한다.

## 3단계: 참조 이미지 입력 최적화

### 구현

- 편집 요청의 참조 이미지를 기본 1장으로 제한했다. 현재 프롬프트는 대표 이미지 한 장만 요구하므로 추가 이미지는 같은 장면에 불필요한 이미지 입력 토큰과 업로드를 발생시킨다.
- 참조 이미지를 디코딩해 긴 변을 최대 1,024px로 축소하고 PNG로 다시 인코딩한다. 이 과정에서 EXIF 등 생성에 필요 없는 메타데이터도 제거한다.
- 최대 4천만 픽셀의 디코딩 한계를 두고, 읽을 수 없거나 한도를 넘은 입력은 모델에 전달하지 않는다.
- 실제 전송된 참조 이미지 수와 전체 바이트를 관측 지표에 추가했다.
- 2,000×1,000 JPEG fixture가 1,024×512 PNG로 축소되고, 작은 이미지는 해상도를 유지하며, 잘못된 이미지는 제외되는 단위 테스트를 추가했다.

## 4단계: 출력 크기와 품질 프로파일 최적화

### 구현

- 출력 설정을 이름 있는 프로파일로 묶었다.
  - `ECONOMY`: 864×1536, `low`
  - `BALANCED`: 1152×2048, `medium`
  - `CUSTOM`: 기존 `OPENAI_IMAGE_SIZE`, `OPENAI_IMAGE_QUALITY` 값을 사용
- 기본 프로파일을 `ECONOMY`로 전환했다. 864×1536은 정확한 9:16이고, 각 변이 16의 배수이며, 1,327,104픽셀로 이미지 API의 유효 범위와 기존 서버 검증을 만족한다.
- 생성과 편집 모두 Spring AI `OpenAiImageOptions`에 해석된 동일 프로파일을 전달하고, 관측 로그에도 실제 적용 크기와 품질을 기록한다.
- `OPENAI_IMAGE_OUTPUT_PROFILE` 하나로 프로파일을 전환할 수 있고, `BALANCED`로 즉시 되돌릴 수 있다.

## 5단계: 모델 라우팅 검증

### 후보 검토

- OpenAI 공식 [GPT Image 2 모델 문서](https://developers.openai.com/api/docs/models/gpt-image-2)는 `gpt-image-2`가 유연한 크기와 이미지 편집을 지원한다고 명시한다.
- 공식 [이미지 생성 가이드](https://developers.openai.com/api/docs/guides/image-generation)는 `gpt-image-2`의 임의 크기 제약과 low 품질을 지원하며, 864×1536은 모든 제약을 만족한다.
- `gpt-image-1-mini`의 1024×1536 low 출력은 장당 $0.006이지만 정확한 9:16이 아니고, 공식 [mini 모델 문서](https://developers.openai.com/api/docs/models/gpt-image-1-mini)는 해당 alias를 deprecated로 표시한다.
- 4단계의 `gpt-image-2` ECONOMY 실측 총비용은 장당 약 $0.00527이며 텍스트·편집 이미지 입력 비용까지 포함한다. 따라서 형식을 훼손하면서 mini로 내릴 비용상 근거도 없다.

### 구현

- 지원 모델 선택을 `TripRecapImageModelRouter`로 분리했다.
- `gpt-image-2`와 고정 snapshot `gpt-image-2-2026-04-21`은 그대로 사용한다.
- 설정에 `gpt-image-1` 또는 `gpt-image-1-mini`가 남아 있으면 정확한 9:16과 편집을 지원하는 `gpt-image-2`로 승격한다.

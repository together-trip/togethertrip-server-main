# 여정도 리캡 데이터 집계·노출 계약 계획

## 작업 정보

- 대상 repo: `togethertrip-server-main`
- GitHub Issue: [#145 여정도 리캡 데이터 집계·노출 계약 설계](https://github.com/together-trip/togethertrip-server-main/issues/145)
- 선행 이슈: [#142 정산 공유 링크](https://github.com/together-trip/togethertrip-server-main/issues/142)
- 상태: 승인 전 계약 초안

## 목표

외부 AI 없이 기존 원장성 데이터를 읽어 여행의 시간·장소·기록·지출·정산을 여정도 리캡으로 표현할 수 있는 데이터 계약을 정한다.

## 데이터 출처 후보

- 여행: 제목, 시작일, 종료일, 국가/도시
- 여행 참여자: 여행 내 표시명, 참여 상태
- 기록: 작성 시각, 장소, 본문, 첨부 존재 여부
- 거래: 소비 시각, 장소, 항목, 결제자, 부담자, 원통화 금액
- 환율: 거래 저장 시점의 기준 통화 금액·환율 스냅샷
- 정산: 확정 상태, 참여자별 잔액, 송금·수령 확인 상태

원장 데이터의 계산 기준을 바꾸지 않는다. 리캡은 조회용 조합이며 정산 결과를 재계산하지 않는다.

## 노출 원칙

- 금액은 `BigDecimal`과 저장된 기준 금액을 사용한다.
- 결제자와 부담자를 구분한다.
- 탈퇴·퇴장 참여자는 기존 원장 채권·채무를 잃지 않으며 현재 표시 정책을 따른다.
- 공유 뷰에는 사용자 ID, 연락처, 내부 식별자를 노출하지 않는다.
- 사진·메모의 공개 여부는 별도 제품·개인정보 결정으로 둔다.
- 정산 미완료 상태의 리캡은 개인 권한과 여행 참여 권한을 적용한다.

## API 방향 후보

### 후보 A: 기존 여행 상세 응답 확장

- 장점: 앱 요청 수가 적다.
- 위험: 여행 상세 응답이 커지고 리캡 집계 책임이 섞인다.

### 후보 B: 리캡 전용 읽기 API

- 장점: 모바일·PWA가 필요한 데이터만 조회하고 버전 관리가 쉽다.
- 위험: 조회 계약, 권한, 집계 비용이 새로 생긴다.

현재 추천은 후보 B다. 단, 실제 쿼리 비용과 데이터 출처가 확인되기 전에는 확정하지 않는다.

## 상태별 정책 초안

- 여행 중: 현재까지 기록과 예상 정산만 제공
- 여행 종료·정산 전: 여정 기록 제공, 정산 시작 안내
- 정산 진행 중: 참여자 본인에게 필요한 정산 상태 제공
- 정산 확정: 확정된 정산 스냅샷과 여정 집계 제공
- 공개 공유: `#142`의 확정 정산·토큰·캐시 정책을 따른다.

## 검증 계획

- 정상 단일 통화 여행
- 다통화 여행과 거래 시점 환율
- 장소·시간 없는 거래
- 한 지출의 부분 참여
- 결제자와 부담자가 다른 거래
- 퇴장·탈퇴 참여자 포함 여행
- 정산 전·후 금액과 확정 스냅샷 일치
- 비참여자·공유 토큰 권한 차단

기술 구현 시 `./gradlew check`와 정산 핵심 로직 테스트를 실행한다.
